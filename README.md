# HTRU1 → PSC AO327 Pulsar Candidate Ranking

A cross-survey experiment: train a small CNN on the public **HTRU1** pulsar
dataset (Parkes, 1.4 GHz), then test whether it can help rank real candidates
from the **PSC AO327** survey (Arecibo, 327 MHz).

Pulsar searches produce far more candidates than anyone can review by hand, and
almost all of them are junk. A model doesn't have to make the final call — it just
has to push the promising ones toward the top of the review queue. This project
measures whether a model trained on *one* survey can do that for *another*.

It is decision support for human reviewers. It does not reject candidates
automatically, and its scores are **not** calibrated probabilities.

## What we found

| Task | ROC-AUC |
|---|---|
| HTRU1 → HTRU1 (in-domain, held-out test batch) | 0.975 |
| PSC: pulsar vs **noise** | 0.952 |
| PSC: pulsar vs **RFI** | **0.617** |
| PSC: pulsar vs RFI — *plain duty-cycle statistic, same inputs* | **0.936** |

The model transfers to a different telescope well enough to reject empty noise,
and essentially not at all for radio interference (RFI): every one of 50 RFI
candidates scored above 0.61, while 10 of 50 real pulsars scored below it. No
threshold separates them.

The last row is the important one. A one-line measurement — *how wide is the
bright blob in phase?* — beats the neural network on the exact task it fails, on
the very same preprocessed images. So the information the model needs is present
in its input; the model just doesn't use it. **This is a transfer failure, not a
problem with the data representation.**

Likely cause: the model learned "bright coherent vertical stripe ⇒ pulsar," which
holds at Parkes/1.4 GHz. Arecibo's 327 MHz interference also makes bright vertical
structure — just broader and often slanted — and the model was never taught to
reject that shape.

Implication: the fix is **fine-tuning / domain adaptation on AO327 data**, not
adding new input channels.

## Repository map

Run things roughly in this order.

**Data and model**

| Path | What it does |
|---|---|
| `src/datasets/htru1_dataset.py` | Loads HTRU1 batches. Keeps channels 1–2 (Frequency–Phase, Time–Phase), scales to `[0,1]`, flips labels so `1.0 = pulsar`. Refuses to mix train and test files. |
| `src/datasets/psc_preprocessing.py` | Turns PSC candidate JSON into the same `(2, 32, 32)` tensor. `arrays_to_tensor()` is the shared resize + normalize core. |
| `src/models/baseline_cnn.py` | `BaselineCNN` — 2 conv blocks → 1 raw logit. 267,345 parameters. No sigmoid in `forward`. |

**Scripts**

| Path | What it does |
|---|---|
| `scripts/validate_htru1_dataset.py` | Sanity-checks the HTRU1 download: counts, shapes, no train/test filename overlap. |
| `scripts/train_baseline.py` | Trains on the 5 HTRU1 train batches, 80/20 split, seed 42, `pos_weight` for imbalance. **Overwrites the best checkpoint silently.** |
| `scripts/evaluate_baseline.py` | Scores the untouched HTRU1 `test_batch`; writes metrics JSON + predictions CSV. |
| `scripts/inspect_psc_candidate.py` | Fetches one PSC candidate and reports array shapes / NaN / ragged issues. No saving, no inference. |
| `scripts/predict_psc_candidate.py` | Scores a single PSC candidate by plot ID. |
| `scripts/build_psc_manifest.py` | Builds the labeled evaluation manifest from the raw PSC tab exports. Hard-fails if any row's grade disagrees with its tab. |
| `scripts/rank_psc_candidates.py` | Scores a whole manifest. Caches JSON, rate-limits fetches, continues past failures, writes a score-sorted CSV. |
| `scripts/diagnose_psc_domain_shift.py` | The EXP-003 diagnostics: axis orientation, category figure, normalization comparison. |

**Data**

| Path | Tracked? |
|---|---|
| `data/raw/htru1-batches-py/` | No — download separately (see below). |
| `data/psc/source/*.tsv` | **Yes** — raw exports of the PSC psrsearch tabs. |
| `data/psc/psc_eval_candidates.csv` | **Yes** — the 150-candidate labeled manifest. |
| `data/psc/raw/*.json` | No — ~59 MB cache, regenerated by rerunning the ranking script. |
| `outputs/models/`, `outputs/metrics/`, `outputs/predictions/`, `outputs/figures/` | **Yes** — checkpoints, metrics, ranked predictions, figures (~9 MB). Hashes are recorded in `experiments/`. |

## Reproducing

```bash
source .venv/bin/activate
python -m unittest discover -s tests      # 67 tests, no network needed
```

HTRU1 data is not in the repo. Get it from
[Zenodo record 3205409](https://zenodo.org/records/3205409) and unpack to
`data/raw/htru1-batches-py/`.

```bash
python scripts/validate_htru1_dataset.py            # confirm 50k train / 10k test
python scripts/train_baseline.py                    # WARNING: overwrites the checkpoint
python scripts/evaluate_baseline.py                 # HTRU1 test metrics
python scripts/build_psc_manifest.py                # rebuild the 150-row manifest
python scripts/rank_psc_candidates.py               # score + rank (uses cache if present)
python scripts/diagnose_psc_domain_shift.py         # EXP-003 diagnostics + figure
```

Back up `outputs/models/baseline_cnn_best.pt` before retraining —
`train_baseline.py` will overwrite it without asking.

## Experiments

Each record is self-contained: config, environment, hashes, results, caveats.

- **[EXP-001](experiments/exp001_htru1_baseline.md)** — HTRU1 baseline locked down.
  Verified the saved metrics regenerate byte-for-byte from the saved checkpoint.
  Test F1 0.716, ROC-AUC 0.975, PR-AUC 0.790.
- **[EXP-002](experiments/exp002_psc_cross_survey_ranking.md)** — first cross-survey
  ranking over 150 labeled AO327 candidates. Found the pulsar/RFI failure. Its
  causal interpretation is superseded by EXP-003; its measurements stand.
- **[EXP-003](experiments/exp003_domain_shift_diagnosis.md)** — diagnosis. Ruled out
  a transposed-axis bug, a phase-bin-count artifact, and normalization mismatch.
  Established that the failure is model transfer, not representation.

## Known limitations

- **Small effective sample.** The 150 candidates are not 150 independent things:
  the 50 positives are ~27 distinct pulsars (one contributes 17 detections), the
  50 RFI rows are essentially *one* ~671 ms zero-DM interference mode, and all 50
  noise rows come from a single pointing. Ranking metrics are reported both
  per-detection and per-source; **trust the per-source numbers.**
- **The duty-cycle result is post-hoc.** That feature was chosen after looking at
  the data. The effect is large but unvalidated on held-out candidates.
- **Scores are not probabilities.** A sigmoid from a model applied across surveys
  is uncalibrated. Call it a "pulsar-likelihood score."
- **Weak candidates are lost in preprocessing.** Squeezing 200 phase bins into 32
  erases marginal pulsars. This is separate from the RFI problem.
- **Six manifest rows are unresolved** — they came from an individual-grading view
  rather than a consensus tab, and one (`6004822`) is graded "Known" despite
  DM = 0.0 and P = 33.3 ms, which looks like mains interference.
- **Not a validated discovery pipeline.** Nothing here should be used to discard a
  real candidate.
